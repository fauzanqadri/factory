Write the architecture for the approved PRD.

1. Read the PRD and the brief. Note every NFR: they decide most of the design.
2. List the components. Each must exist because a requirement needs it.
3. Describe the data: entities, fields, owners, where each lives.
4. Define every interface: name, inputs, outputs, errors.
5. Record each significant decision as D-1, D-2, ... with the options considered and why this one won.
6. Fill "Requirements coverage" so every FR and NFR maps to a component. A requirement with no component is a gap: fix it.
7. List risks with a mitigation, or mark them accepted with a reason.
8. Answer the checklist, then submit.

Done when: coverage is complete, every interface is defined, and every decision has its reasons.
